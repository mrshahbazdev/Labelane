# Labelane

Thermal label and barcode designer for Windows. Design a label once, load a CSV,
print a few hundred.

## Why it works the way it does

Everything is laid out in **millimetres**, and the printer is told the page is
exactly that many millimetres. There is no scaling step anywhere, so a 50 x 25 mm
label comes out 50 x 25 mm.

The canvas preview and the printed output are generated by the **same module**
(`src/lib/labelHtml.js`). What you see is what prints — there is no second
rendering path to drift out of sync.

## Getting started

```bash
npm install
npm run dev
```

Press **Sample** in the data panel to load three example rows and see the
starter template bind to them.

## Data

Load a `.xlsx`, `.xls` or `.csv` file. The first sheet is used.

A `__copies` column sets how many of that row to print. Otherwise the
template's copies setting applies to every row.

## Dynamic fields

Anything in double braces is resolved once per label. Press **Fields** in the
data panel for the full reference.

| | |
|---|---|
| `{{sku}}` | a column, matched case-insensitively |
| `{{serial:start=1000,pad=5}}` | auto-increment, one per label |
| `{{row}}` | label number within the run |
| `{{date:+180,format=MM/YYYY}}` | dates with offsets, for expiry |
| `{{= price * 1.17 }}` | arithmetic across columns |
| `{{= [unit price] * [qty] }}` | `[]` for column names with spaces |
| `{{title\|upper}}` | transforms, chained with `\|` |
| `{{price\|money:Rs}}` | `Rs 7,499.00` |
| `{{note\|default:N/A}}` | fallback when blank |

A placeholder with no matching column prints as written, so the mistake shows
up on the proof rather than as a silent blank on 500 labels.

Expressions are parsed and evaluated by a small shunting-yard implementation,
not `eval` or `new Function`. The packaged app runs under `script-src 'self'`,
so anything eval-shaped would be blocked in production even if it worked in dev.

## Text handling

**Shrink to fit** drops the font size automatically when a long value would
overflow its box. With variable data this is the difference between a usable
template and one that breaks on every third row.

**Hide when empty** drops the element entirely when its value resolves to
nothing, so a stray "Rs" or an empty barcode box never prints.

**Right-to-left** for Urdu and Arabic text.

## Barcode symbologies

Linear: Code 128, EAN-13, EAN-8, UPC-A, Code 39, Code 93, Codabar, ITF-14,
MSI, Pharmacode.

2D and GS1: **Data Matrix**, **GS1 Data Matrix**, **GS1-128**, **PDF417**,
**Aztec**, QR.

The 2D and GS1 set is rendered by bwip-js, which is loaded on first use rather
than at startup — it is about a megabyte, and most labels only ever need Code
128 or EAN-13.

Invalid values print a visible red error box rather than a blank space.
JsBarcode does not throw on a value its symbology rejects — it reports through a
callback and renders nothing — so a mistyped EAN-13 would otherwise print as a
silent empty box on every label in the run.

## Printing

**Print** sends directly to the selected printer. **Save PDF** writes to the
app's output folder.

Set the label size in the printer driver as well. Windows drivers for thermal
printers keep their own page size, and if it disagrees with the document the
driver usually wins.

## Building

```bash
npm run dist:win
```

The three `appx` identity values in `package.json` come from Partner Center
(Product identity page) and must match it exactly for the Store to accept the
package.

On recent Windows 11 builds the `makeappx.exe` that electron-builder 24 ships
in its winCodeSign bundle fails with "side-by-side configuration is incorrect",
and fails again when run from `%LOCALAPPDATA%\electron-builder`. This machine
has a working copy of the bundle, with the Windows SDK 10.0.26100 packaging
tools swapped in, at `%USERPROFILE%\.eb-cache`. Point the build at it:

```powershell
$env:ELECTRON_BUILDER_CACHE = "$env:USERPROFILE\.eb-cache"; npm run dist:win
```

Store images are generated rather than hand-drawn:

```bash
npm run store:assets        # icons, tiles, splash, Store logos from build/logo-mark.svg
npm run store:screenshots   # 1920x1080 screenshots from the built app
```

## Sheet layout

For laser and inkjet printers using A4 label sheets. Turn on **Sheet layout**
in the inspector and pick a preset (24-per-A4, 65-per-A4 and so on), or set
columns, rows, margins and gaps by hand.

Cells are positioned with absolute millimetre coordinates rather than CSS grid.
Grid gaps round to device pixels, and at 300dpi that rounding walks the last
column several millimetres off the die-cut, which ruins the sheet.

The inspector warns when the grid does not fit the page, before you print.

## Editing

- Multi-select with shift-click or by dragging a marquee on empty space
- Align and distribute, against the label for one element or against the
  selection's bounding box for several
- Smart guides snap to the label's centre lines and to other elements' edges
  and centres. Hold **Alt** to ignore snapping
- Resize from any corner; hold **Shift** to keep the aspect ratio
- Layers panel for z-order, lock and hide
- Undo/redo, with a whole drag collapsing into one history entry

## Printing

**Print** sends directly to the selected printer, **Save PDF** writes to the
app's output folder. Choose all rows, just the previewed row, or a range.

The print dialog previews the real print HTML in an iframe, so clipped
elements, failed barcodes and unmatched placeholders show up before the roll
is spent rather than after.

Set the label size in the printer driver as well. Windows drivers for thermal
printers keep their own page size, and if it disagrees with the document the
driver usually wins.
